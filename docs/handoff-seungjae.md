# 승재 담당 작업 인계

작성 기준: 2026-10-10, macOS 26.6.2 arm64, 프로젝트 Python 3.13.14

## 가장 최근 변경 — 전체 화면과 중앙 확대 정밀 입력

- 초인종 버튼, 손가락, 누르기, 접촉처럼 작은 대상의 상대 위치가 핵심인 목적을 `fine_detail`로 분류합니다. 최대 1920px 원본 프레임을 추출한 뒤, 각 원본 시각마다 위쪽 전체 화면과 아래쪽 중앙 60% 확대 보기를 1280×1080 이미지 한 장에 구성해 로컬 VLM에 전달합니다. 서로 다른 시각을 한 이미지로 합치지 않으며 원본 영상과 추출 프레임은 수정하지 않습니다.
- 중앙 확대가 화면 가장자리 대상을 놓칠 수 있으므로 전체 화면 보기를 함께 유지합니다. 이 구성은 모델이 작은 대상을 반드시 찾는다는 보장이 아니라 입력 가시성을 높이는 휴리스틱입니다. 결과의 `input_representation`은 `fine_detail_overview_center_crop`으로 기록합니다.
- 작은 접촉 목적의 움직임 탐색은 반복·미세 전역 점수보다 변화 정점 중심의 `general_peak`를 사용합니다. 선택 구간을 계획에 적용하면 정점 주변 촘촘한 원본 시각을 사용하며, 계획 화면에 최대 1920px 원본과 1280×1080 전체·중앙 확대 입력을 명시합니다. 픽셀 변화는 버튼 접촉 확률이나 행동 판정이 아닙니다.
- 프롬프트 버전은 `candidate-recall-v9-overview-detail-crop`입니다. 전체 보기와 확대 보기가 같은 원본 시각임을 명시하고, 손·손가락과 버튼·물체의 간격·겹침·접촉 가능성을 우선 관찰하되 실제 압력·작동 여부와 프레임 사이 동작은 불확실성으로 남깁니다.
- Ollama가 최종 JSON `content` 없이 `thinking`만 반환하면 일반 빈 응답과 구분한 명시적 실패로 처리합니다. UI는 분석 시작 시 이전 성공 배너를 실행 중 상태로 바꾸고, 실패 시 실패한 모델 ID와 오류를 상단 배너와 결과 목록에 남깁니다. 입력이 바뀌면 이전 결과 배너도 현재 모드 상태로 초기화합니다.
- 직전 v8 개별 프레임 방식은 사용자가 `qwen3-vl:4b-instruct`로 92~98초 범위와 버튼 주변의 더 좁고 촘촘한 범위를 각각 실행했습니다. 두 작업은 실제 모델 응답으로 42.1초와 34.3초에 완료됐지만 모두 후보 0개였습니다. 이는 연결 실패가 아니라 해당 입력과 4B 모델의 미탐지이며, 같은 설정 재시도는 중단했습니다.
- v9 전체·중앙 확대 방식은 사용자가 새 앱에서 먼저 확인했습니다. 그러나 저장 결과 `local-f3da30aae078.json`의 영상 ID `3ca4f41d78465da8`을 대조하니 선택 영상은 유모차 파일이었고 목적은 초인종 접촉이었습니다. 이 작업은 47.660초에 `completed`, `real_model`, 10/10프레임, 배치별 후보 `(0, 0, 0)`으로 정상 종료했지만 영상–목적이 불일치하므로 초인종 탐지 성능 근거로 사용하지 않습니다. UI·정밀 입력·저장 연결 확인으로만 기록합니다.
- 올바른 초인종 영상 ID `7b9f9a0a3ba37350`에서 동일한 97.0~99.5초, 원본 시각 10개, 전체+중앙 확대 1280×1080 입력, v9 프롬프트로 공정한 4B 기준선을 다시 측정했습니다. `qwen3-vl:4b-instruct`는 47.214초에 `completed`, `real_model`, 10/10프레임으로 끝났지만 배치별 후보는 `(0, 0, 0)`이었습니다. 결과는 `compare-4b-v9-e953bc2a17fb.json`에 저장했습니다. 실제 공급자 시간 46.126초 중 prompt/image evaluation은 44.186초, 생성은 0.566초였습니다.
- 같은 영상·목적·원본 시각·입력 표현·16K context·출력 800 token을 유지하고 설치된 `qwen3-vl:8b`로 비교했습니다. 로컬 `/api/show`는 vision과 `think=false`를 지원한다고 표시했으며 앱도 `think:false`를 보냈지만, 첫 배치가 67.674초 뒤 최종 JSON content 없이 thinking만 반환했습니다. 명시적 실패로 처리하고 남은 두 배치와 자동 재시도는 실행하지 않았습니다. 이 결과는 후보 없음이 아니라 비교 불가능한 응답 실패입니다.
- 사용자의 명시 승인 후 비사고형 `qwen3-vl:8b-instruct` 약 6.2GB를 로컬 Ollama에 설치했습니다. `/api/show`에서 8.8B Q4_K_M, `vision`, context 262144, `thinking=false`를 확인했습니다. 공정 비교는 앱 한도 16K context·800 output token을 그대로 유지했습니다.
- 올바른 초인종 영상에서 4B와 동일한 97.125~99.375초 요청 시각 10개를 8B instruct에 전달했습니다. 3요청 모두 JSON·근거 검증을 통과했고 110.743초에 `completed`, `real_model`, 배치별 후보 `(1, 1, 1)`로 종료됐습니다. 근거 원본 시각은 97.130~99.399초이며, 손가락과 벽면 초인종 장치의 근접·중첩을 관찰했지만 실제 압력·작동·반복 누름은 단정하지 않았습니다. 결과는 `compare-8b-instruct-v9-74afed0bfdf3.json`에 저장했습니다.
- 재빌드한 `.app`에서 사용자가 `qwen3-vl:8b-instruct` 실행·실제 후보 표시·근거 시각 98.131~99.399초·후보 선택 후 원본 01:38~01:39 이동을 수동 확인했습니다. 확인용 구간이 짧지만 원본 화면과 맞는다고 확인했습니다.
- 실제 응답이 노출한 0.001초 반올림과 decoded PTS의 0.0003초 차이를 큰 범위 불일치로 처리하는 경계 문제를 발견했습니다. 이제 0.001초 이하는 정확한 PTS까지 최소 확장하고 반올림 보정을 불확실성에 기록합니다. 자동 테스트는 110개 통과했습니다.

## 최종 후속 변경 — 시간순 비교 보드

- 로컬 `temporal_sequence` 분석은 원본 프레임을 개별 이미지 여러 장으로만 보내지 않고, 최대 4개를 FFmpeg로 최대 2×2 행 우선 비교 보드 한 장에 구성해 모델에 전달합니다. 원본 영상과 추출 프레임은 수정하지 않습니다. 외부 모드는 승인 manifest와 실제 전송 내용을 일치시키기 위해 개별 프레임을 유지합니다.
- 공급자에는 비교 보드 한 장이 전달되지만 응답은 원본 frame ID와 decoded PTS로 검증합니다. 결과의 `ModelExecutionInfo`에는 원본 프레임 수·크기와 실제 공급자 이미지 수·크기·`input_representation`을 따로 저장합니다.
- 계획 화면은 “원본 프레임 최대 4개를 최대 2×2 시간순 비교 보드로 묶음”을 명시합니다. 일반 균등·변화 정점 분석은 기존 개별 이미지 방식을 유지합니다.
- `candidate-recall-v6-temporal-storyboard` 정식 실제 검증은 `qwen3-vl:4b-instruct`에 64.2642·66.7667·69.2692·71.7717초 원본 프레임 4개/비교 보드 1장을 전달했습니다. 1요청, wall 5.245초, provider 4.792초, `completed`, `real_model`, 4/4프레임이었지만 후보는 0개였습니다. 따라서 연결은 확인했으나 두리번거림 탐지 개선은 확인하지 못했습니다.
- 별도 단순 비교 보드 진단 1회에서는 화면 왼쪽에서 오른쪽으로 머리·얼굴 방향이 바뀐다는 후보 문장이 생성됐습니다. 다만 `evidence`가 앱의 관찰 문장 계약을 통과하는지 정식 파서로 확인한 결과가 아니므로 앱의 실제 후보 성공으로 세지 않습니다.
- 이 단계의 코드는 `candidate-recall-v7-temporal-panel-checklist`였습니다. 현재는 위의 v9 전체·중앙 확대 정밀 접촉 분기로 확장됐습니다. v7 방향 비교 자체는 실제 요청 한도 소진 뒤 작성되어 자동 테스트만 통과했고 실제 4B/8B 결과는 미검증입니다.
- 이 후속 검증의 실제 공급자 요청은 총 6회입니다: 개별 이미지 v4 3회, 개별 이미지 v5 1회, 단순 비교 보드 진단 1회, 정식 v6 비교 보드 1회. 외부 API 호출과 새 모델 다운로드는 없었습니다.
- 전체 자동 테스트 102개가 통과했습니다. 비교 보드 생성 통합 테스트는 합성 H.264 원본 네 장을 960×540 한 장으로 만들고 원본 해시가 바뀌지 않음을 확인하며, 가짜 외부 공급자 테스트는 승인된 개별 이미지 수가 유지됨을 확인합니다.
- 최종 소스로 개발용 `.app`을 다시 빌드했습니다. arm64·113MB·ad-hoc 서명·TeamIdentifier 없음이며 offscreen 자동 종료 smoke는 종료 코드 0입니다. 실제 화면에서 v7 계획 문구와 후보 표시는 아직 수동 미검증입니다.

## 최신 후속 변경 — 반복·미세 시간 변화

- 목적에 `두리번`, `주변을 살피`, 머리·얼굴·몸통 방향 변화, 반복 동작 표현이 있으면 `temporal_sequence` 분석 전략을 자동 선택합니다.
- 이 목적의 로컬 전처리는 160px 회색조 표본을 8×5 타일로 나누고 변화가 큰 상위 20% 타일을 비교합니다. 단발성으로 매우 큰 전역 변화는 감점하고 10초 동안 분산된 국소 변화를 우선합니다. OpenCV 같은 새 의존성은 추가하지 않고 기존 FFmpeg와 Python 표준 라이브러리만 사용했습니다.
- 일반 목적의 기존 `general_peak` 6초 후보와 변화 정점 중심 샘플링은 보존했습니다. 반복·미세 후보는 한 구간 전체에 12장 또는 여러 구간 각각에 4장씩 시간순으로 분산합니다.
- 계획 fingerprint, 분석 요청, 저장 결과에 `sampling_strategy`와 `observation_guidance`를 추가했습니다. 관찰 기준은 “눈치를 본다”는 심리 판단 대신 서로 다른 시각의 머리·얼굴·몸통 방향 변화를 비교하도록 표시합니다.
- 이 단계에서 사용한 v4는 개별 이미지 입력이었으며 후보 0개였습니다. 이후 비교 보드와 v7 패널 체크리스트로 대체됐고, 목적과 무관한 큰 움직임을 대신 반환하지 않으며 반복·방향 변화 주장에는 서로 다른 근거 시각 2개 이상을 계속 요구합니다.
- 제공 영상에서 VLM 없이 새 전처리만 실행한 결과 상위 후보는 `78.5~88.5`, `63~73`, `88.5~98.5`, `98.5~108.5`, `110.087~120.087초`였습니다. 앞 두 후보는 사용자가 알려 준 63~91초와 겹칩니다. 이는 알려진 한 영상의 픽셀 변화 연결 확인이며 새 프롬프트의 실제 탐지 성공이나 정확도 검증이 아닙니다.
- 반복·미세 전처리 단계 당시 자동 테스트는 99개였습니다. 이후 비교 보드와 외부 전송 불변 테스트까지 포함한 현재 전체 테스트는 102개이며, 실제 Ollama 후속 요청은 위 최종 변경 절에 별도로 기록했습니다. 외부 API는 호출하지 않았습니다.
- 변경 소스로 개발용 `.app`을 다시 빌드했습니다. arm64·113MB·ad-hoc 서명·TeamIdentifier 없음이며 `VIDEO_AGENT_SMOKE_EXIT_MS=250`, offscreen 실행은 종료 코드 0이었습니다. 실제 화면의 새 프로필 목록과 오디오는 이 빌드에서 수동 미검증입니다.

## 1. 구현·수정한 내용

- 설치 Ollama 모델의 `/api/show` vision capability를 확인하고 `qwen3-vl:4b-instruct`를 우선 선택합니다.
- 모델명이 없을 때 추가 질문 답변을 모델명으로 잘못 사용하는 경로를 제거했습니다.
- 로컬 계획은 12개 원본 timestamp를 시간순 4프레임 묶음 3개로 처리합니다. 공급자 자동 retry는 없고 세 요청이 프레임 추출부터 검증까지 하나의 300초 deadline을 공유합니다.
- 배치 경계의 후보를 임의로 합치지 않습니다. 뒤 배치가 실패하면 앞의 검증 결과만 `partial`로 구분합니다.
- `completed` 빈 결과, `partial`, `failed`, `canceled`를 구분하고 응답이 없는 실패·취소는 `origin=none`입니다. 취소 결과는 저장하지 않습니다.
- 모델 응답의 확인용 재생 범위가 실제 근거 프레임 원본 시각을 포함하는지 검증합니다.
- 후보 UI에서 “확인용 재생 범위”와 “관찰 프레임 원본 시각”을 따로 표시합니다. 후보 없음도 오류와 구분해 표시합니다.
- 결과 JSON에 목적·범위·요청 timestamp, 실제 frame ID·decoded timestamp·해상도, 모델 context·출력 한도·요청 수, 전체/공급자 단계 시간과 결과 출처를 저장합니다. 원본 경로와 키는 저장하지 않습니다.
- 진행률을 모르는 실제 추론은 퍼센트를 만들지 않고 단계·배치·경과 시간을 표시합니다.
- 취소 뒤 HTTP server 계산 종료를 확정할 수 없으므로 worker가 응답 또는 timeout으로 끝날 때까지 새 분석과 입력 변경을 잠급니다.
- FFmpeg 추출 JPEG는 960px보다 작은 영상을 확대하지 않으며 실제 출력 해상도를 기록합니다.
- FFmpeg 저해상도 프레임 차이 기반 움직임 제안을 추가했습니다. 일반 프로필은 최대 600개 표본에서 비중첩 6초 구간을, 반복·미세 프로필은 비중첩 10초 구간을 최대 5개 제안하며 행동 판정이나 AI 결과로 저장하지 않습니다.
- 움직임 후보를 선택해 `분석 범위로 적용`하면 기존 승인이 폐기되고 약 0.5초 간격 최대 12프레임의 새 계획을 만들어 다시 승인해야 합니다. 적용만으로 VLM이 자동 실행되지 않습니다.
- 촘촘한 배치는 인접 프레임의 자세·신체 부위·물체 위치 변화를 비교하도록 prompt를 구분합니다.
- 승인 범위 안의 모델 확인용 범위가 인용 근거 시각을 포함하지 못하면 근거 앞뒤 1초로 대체하고 원래 값과 보정 사실을 불확실성에 기록합니다. 승인 범위 초과·역전은 계속 거부합니다.
- 모델이 `evidence`에 관찰 설명 없이 frame ID 자체만 복사하면 형식 오류로 처리하고, prompt와 Ollama JSON schema에도 관찰 근거와 frame ID의 역할을 분리해 명시했습니다.
- 여러 배치가 같은 관찰 요약을 반환하더라도 확인 범위가 겹치고 실제 근거 시각이 1초 이내로 이어질 때만 하나로 묶습니다. 모든 근거와 묶음 사실을 유지하며 다른 요약·떨어진 시각은 합치지 않습니다.
- 현재 코드는 `candidate-recall-v9-overview-detail-crop` 프롬프트 버전, 완료 배치별 원시 후보 수, 원본 프레임과 실제 공급자 이미지를 따로 저장합니다. 이 필드는 정확도나 행동 점수가 아닌 재현성 진단 정보입니다.
- 움직임 후보는 상위 3개가 기본 선택되며 사용자가 최대 3개를 조정할 수 있습니다. 한 후보면 변화 정점 주변 12장, 두세 후보면 각 정점 주변 4장씩 총 8장 또는 12장으로 계획하고, 적용 즉시 기존 승인을 폐기합니다.
- 오른쪽 분석 패널을 세로 스크롤 구조로 바꾸고, 움직임 변화 제안 목록과 분석 계획에 최소 높이를 설정해 작은 창에서 콘텐츠가 눌리지 않게 했습니다. 전체 UI는 상단 버튼 또는 `⌘+`, `⌘-`, `⌘0`으로 75~150% 확대·축소합니다.
- 움직임 선택을 후보별 체크박스로 바꾸고 `선택한 분석 구간: n/3`, 선택 시간 목록, 개별·전체 해제 버튼을 추가했습니다. 계획은 등록된 모든 구간을 번호로 나열하고 입력 구간 수와 결과 수가 다를 수 있음을 명시합니다.
- '오래 머무름' 등의 초·분 기준이 없으면 Agent가 `duration_threshold`을 묻습니다. 지속성을 단정한 모델 결과는 복수 관찰 시각과 승인 기준을 충족해야 하며, UI는 표본 간 경과 시간과 중간 연속성 미확인을 표시합니다.

공통 변경 파일은 `src/video_agent/contracts.py`, `agent/planning.py`, `analysis/vision.py`, `models/config.py`, `models/provider.py`, `video/frames.py`, `ui/main_window.py`입니다. 계약 변경 이유와 예시는 `docs/contracts.md`에 같이 반영했습니다.

## 2. 실제 모델과 최종 설정

- 런타임: Ollama 0.40.2, loopback `/api/chat`
- 최종 기본 모델: `qwen3-vl:4b-instruct`(설치 크기 약 3.3GB)
- context: 16384 token
- 출력 한도: 800 token, temperature 0, thinking 비활성
- 입력: 일반 원본 근거는 현재 파일 기준 960px 이하 JPEG 최대 12개. 일반 `temporal_sequence`에서는 원본 4개를 최대 2×2 960×540 비교 보드 한 장으로 구성합니다. 작은 접촉 정밀 목적은 최대 1920px 원본을 바탕으로 각 시각별 전체 화면과 중앙 60% 확대 보기를 1280×1080 한 장으로 구성합니다.
- batching: 원본 시간순 4개씩 최대 3회. 시간 변화 전략의 실제 공급자 이미지는 최대 3장이고 원본 frame ID·PTS는 별도 유지
- 실행 한도: 전체 작업 300초, provider retry 0회, 자동 재분석 0회
- fallback: 로컬 실패 시 샘플/외부로 자동 전환하지 않음

`qwen3-vl:8b` 기본 태그는 thinking variant이며, 동일 조건 비교에서 `think:false`에도 첫 배치가 67.674초 뒤 thinking만 반환하고 최종 content가 없어 명시적으로 실패했습니다. 같은 태그는 재시도하지 않았습니다. 별도 `qwen3-vl:8b-instruct`는 사용자 승인으로 설치했고 동일 입력의 실제 구조화 응답과 후보 3개를 확인했습니다. 기본 모델은 자원 비용이 작은 4B instruct로 유지합니다.

## 9. Git 상태와 남은 문제

- 브랜치: `codex/local-vlm-ollama`
- `main`의 초기 구현 `0635f02`는 이미 원격에 있음
- 현재 상태는 수정된 추적 파일 24개와 새 `src/video_agent/video/motion.py`, `src/video_agent/analysis/evidence.py` 2개이며 모두 미커밋입니다. 별도 미추적 `공훈의대표님(AI_AGNET)/` 디렉터리는 이번 작업 시작부터 있던 사용자 파일로 보고 열거나 수정하지 않았습니다. push·PR·merge하지 않았습니다.
- 새 번들은 반올림 보정 수정까지 포함해 재빌드했고 offscreen smoke 프로세스는 종료 코드 0으로 자동 종료됐습니다. 사용자가 이 번들에서 실제 8B instruct 실행·후보 표시·원본 seek를 수동 확인했습니다. 영상 원본에는 오디오가 없으며, 서명·공증·외부 배포는 미수행입니다.
- 영상, 결과, 캐시, 모델 weight, `.env`, 키, build 산출물은 Git 추적 대상이 아님

희소한 균등 12프레임의 미탐지는 일반 움직임 제안과 반복·미세 변화 제안으로 보완했습니다. 남은 핵심 문제는 목적별 픽셀 전처리가 사람·신체 부위를 인식하지 않아 카메라 흔들림이나 다른 국소 변화도 제안할 수 있다는 점, 8B instruct가 4B가 놓친 초인종 근접 후보를 반환했지만 단일 시각을 이미 아는 영상이라 정확도를 일반화할 수 없다는 점, 8B가 4B보다 두 배 이상 느렸고 출력 토큰을 거의 소진했다는 점, 중앙 밖 작은 대상은 확대 영역에서 빠질 수 있다는 점, 여러 실제 후보가 배치별로 유사하게 나와도 요약 문구가 다르면 중복 정리되지 않을 수 있다는 점입니다. Python `urllib` 기반 단일 HTTP 호출은 취소 event만으로 Ollama server 계산 중단을 확정하지 못하므로 UI가 worker 종료까지 재실행을 막는 수준이며, 서버 측 즉시 취소는 미구현입니다.
