## 승재가 돌아와서 확인할 작업

1. 실제 화면 수동 확인
   - 사용자가 재생 화면과 움직임 후보 목록이 구간별로 나뉘는 것을 확인했습니다. 재빌드한 `.app`에서 `qwen3-vl:8b-instruct` 실제 후보와 98.131~99.399초 근거가 표시되고, 후보 선택 시 원본이 01:38~01:39로 이동하는 것도 사용자가 수동 확인했습니다.
   - 재생 영상 프레임, 오디오, 버튼 배치, 모달 오류를 직접 확인합니다.
   - 완료 기준: 아래 수동 절차를 실제 화면에서 수행하고 사용 영상 codec과 결과를 기록합니다.
   - 새 빌드에서는 움직임 상위 3개 체크, `n/3` 카운터, 선택 시간 목록, 개별·전체 해제, 다중 후보 계획의 모든 범위·12개 timestamp 표시를 추가 확인합니다.
2. 새 영상 블라인드 행동 탐지 검증
   - 제공 영상에서는 전체 범위의 FFmpeg 움직임 탐색이 92~98초를 최상위로 제안했고, 사용자가 적용·승인한 0.5초 간격 12프레임에서 실제 후보 4개가 생성됐습니다.
   - 이 영상은 개발자가 수동 행동 시각을 이미 알고 있었으므로 정확도 평가가 아닙니다. 다음에는 정답 시각을 분석기에 넣지 않은 별도 영상을 사용합니다.
   - 완료 기준: 움직임 제안 순위, 선택 이유, 실제 후보·미탐지, 사람이 확인한 시각과 처리 시간을 최소한의 개발/확인 분리 원칙으로 기록합니다.
   - 새 반복·미세 프로필은 제공 영상에서 63~73초, 78.5~88.5초, 88.5~98.5초를 상위 후보로 냈습니다. 개별 이미지 방식의 v4/v5와 정식 비교 보드 v6의 실제 4B 응답은 후보 0개였습니다. 단순 비교 보드 진단에서는 방향 변화 설명이 나왔지만 앱 근거 계약까지 검증한 결과가 아니었습니다. v8 정밀 접촉 입력도 사용자가 두 범위에서 실제 4B로 실행했으나 후보 0개로 완료됐습니다. 직전 v9 수동 결과는 유모차 영상에 초인종 목적을 적용한 불일치 작업이라 성능 근거에서 제외했습니다. 올바른 초인종 영상의 공정 v9 비교에서 4B instruct는 47.2초·후보 0개, 사용자 승인으로 설치한 8B instruct는 110.7초·후보 3개였습니다. 8B 후보의 근거는 97.130~99.399초의 손가락–초인종 근접 관찰이며 실제 누름·작동 여부는 미확인입니다. 단일 알려진 영상이므로 정확도 평가가 아니며, 다음은 블라인드 영상에서 같은 기준으로 비교합니다.
   - 완료 기준 추가: 같은 영상에서 목적을 두리번거림의 관찰 가능한 방향 변화로 입력해 후보의 복수 근거 시각과 원본 재생을 확인하되, 이 한 건을 정확도 평가로 간주하지 않습니다.
3. 실제 공급자 연동 여부 결정
   - OpenAI API 프로젝트의 비용·개인정보·보관정책을 검토하고 계정에서 쓸 수 있는 이미지 입력 모델 ID를 선택합니다.
   - 완료 기준: 키를 UI 또는 `OPENAI_API_KEY`로 제공한 뒤 별도 승인 화면의 목적·프레임·목적지와 실제 payload가 일치하는지 사용자 입회하에 최소 1회 확인합니다. 실제 키·프레임을 자동 테스트에 사용하지 않습니다.
4. 배포 정책
   - 지원할 최저 macOS에서 다시 빌드하고 인증서 서명·공증 여부를 별도 결정합니다.
   - 완료 기준: 새 사용자 계정에서 `.app`, FFmpeg 발견, 사용자 데이터 경로를 확인합니다.

## 수동 확인 절차

1. `PYTHONPATH=src ./.venv/bin/python -m video_agent`로 실행합니다.
2. 파일 선택 취소, 텍스트 파일, 손상 영상, 한글·공백 경로 영상을 확인합니다.
3. MP4 재생·일시정지·timeline 이동·오디오를 확인합니다.
4. 짧고 모호한 목적에서만 추가 질문이 나타나는지 확인합니다.
5. 계획에 대상·원본 범위·샘플링·시간/프레임/모델 요청 횟수·요청당 프레임 한도가 보이는지 확인합니다.
   - 두리번거림 목적에서는 계획의 표본에 `반복 변화 비교용 원본 시각`, 구간 전체에 분산한 시간순 비교와 관찰 기준이 표시되는지도 확인합니다.
6. 승인 전 실행할 수 없고 목적·분석 방식·범위·우선 확인 상황을 바꾸면 계획 만들기부터 다시 거쳐야 하는지 확인합니다.
7. 외부 모드에서 키가 암호형으로 보이고 앱 재시작 후 남지 않는지, 분석 승인만으로 실행되지 않고 전송 공급자·목적지·프레임 시각을 별도 승인해야 하는지 확인합니다. 실제 외부 호출은 승인된 검증 시간에만 수행합니다.
8. 샘플 실행 중 UI 반응, 취소, 중복 실행 차단, 후보 클릭 원본 이동을 확인합니다.
9. 로컬 모드 빈 결과와 `partial` 결과가 실패·샘플 결과와 다르게 보이는지 확인합니다.
10. 앱 종료 후 `~/Library/Application Support/VideoAnalysisAgent` 결과와 `reviews/` 검토 기록을 다시 읽을 수 있는지 확인합니다.
11. `dist/VideoAnalysisAgent.app`은 build 성공과 별도로 Finder에서 화면·영상 재생을 확인합니다.
12. 단계 표시줄과 이전·다음 버튼으로 ①②③을 오가도 입력·계획·승인 상태가 유지되는지, ② 단계에서 승인·실행 버튼이 스크롤과 상관없이 보이는지, 창을 줄이거나 화면 크기를 바꿔도 ③ 단계 목록과 기록 영역이 쓸 수 있는 크기인지 확인합니다.
13. ③ 단계에서 판단·메모·태그·북마크를 입력하고 다른 후보로 갔다 와도 남는지, 미저장 표시·`기록 저장`·`되돌리기`·필터·정렬·범위 재생 3종(범위 끝에서 멈춤)을 확인합니다. 저장 없이 앱을 닫거나 다른 영상을 열 때 확인 창이 뜨는지도 봅니다.
14. 앱을 다시 시작해 `저장된 결과`에서 같은 결과를 열면 기록이 복원되는지, `분석 완료`가 미검토·미저장 항목을 경고하고 완료 시각을 표시하는지 확인합니다.
15. `결과 요약`에서 6개 영역과 출처 배너를 확인하고, 문구를 고쳐 HTML로 내보낸 뒤 브라우저에서 엽니다. ⑤의 법령 링크가 요약 창과 HTML 모두에서 열리는지 확인합니다.
16. ① 단계 `CCTV 영상`에 영상 2개를 추가하고, 목록에서 영상을 바꿔도 시각 오차가 영상별로 남는지, 분석 뒤 목록 상태가 바뀌는지 확인합니다. 사건을 저장하고 앱을 다시 시작해 사건을 열면 `파일 연결`로 같은 파일만 다시 연결되는지 봅니다.
17. 두 영상 모두 분석한 뒤 ③ 단계의 카메라 탭으로 결과를 오가고, `전체 후보`에서 다른 카메라 후보를 두 번 눌러 이동하는지 확인합니다. `결과 요약`이 `사건 전체`로 열려 카메라별로 묶이는지, `현재 카메라`로 바꿀 수 있는지 확인합니다.
18. 로컬 VLM 모드에서 영상 일부 범위(예: 아무 일도 없는 10초)를 분석해 후보가 0개이면 ③에 `범위 확대 제안`이 나오는지, `영상 전체로 범위 넓히기`가 범위를 `영상 끝`까지 바꾸고 ②로 이동하되 다시 승인하기 전에는 실행할 수 없는지 확인합니다. 샘플 모드는 항상 후보를 만들어 제안이 나오지 않습니다.
19. ① 분석 단서에서 출처·확실성·분석 사용이 구분되는지, 긴 단서가 줄바꿈되는지, 단서를 골라 문장·출처·확실성을 고치고 `삭제`·`선택 해제`가 동작하는지, 체크박스가 기존처럼 분석 사용만 바꾸는지 확인합니다. 저장한 사건을 다시 열어 단서와 카메라 정보가 그대로 나오는지도 봅니다.
20. 화면이 Pretendard GOV와 KRDS 크기·색으로 보이는지, 1440×900 창에서 ①②가 잘리지 않는지, 화면 크기 130·150%에서 가로 스크롤이 없는지 확인합니다.
21. ①에서 사건 유형을 고르면 추천 상황이 체크되고 비어 있는 분석 목적이 채워지는지, 체크를 바꾼 뒤에는 유형을 바꿔도 체크가 유지되는지, 직접 입력 힌트를 추가·삭제할 수 있는지 확인합니다. 사건을 저장하고 다시 열어 유형·상황·힌트가 복원되는지, ② 계획 표에 `우선 확인 상황`이 보이는지 봅니다.
22. ② `분석 방식`에 이 컴퓨터의 모델이 `빠른 분석`·`정확한 분석`으로 보이고 `:cloud` 모델은 없는지, 바꾸면 상태 줄과 계획 표가 바뀌는지, `다시 확인`이 목록을 다시 읽는지 확인합니다. 새 사용자 데이터 폴더로 처음 실행하면 `빠른 분석`으로 시작하는지도 봅니다.
23. ① 발생 시각을 `미확인`으로 두면 날짜 칸이 없고, `확인`·`추정`으로 바꾸면 칸이 나타나 누르면 달력이 열리는지, `안내`를 누르면 말풍선 안내가 열리고 Esc로 닫히는지 확인합니다.
24. 분석 결과가 있는 영상에서 재생 막대에 후보 구간이 판단별 색으로 표시되는지, 판단을 저장하면 색이 바뀌는지, 표시를 누르면 해당 후보가 선택되고 재생 위치가 옮겨지는지 확인합니다.

자동 테스트·오프스크린 UI·합성 영상·실제 화면·실제 VLM은 서로 다른 검증 수준입니다. 실제 VLM 연결 성공도 특정 행동 탐지 성공을 뜻하지 않습니다.
