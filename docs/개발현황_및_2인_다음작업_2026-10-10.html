영상 데이터 중요 구간 선별 Agent

개발 현황과 2인 다음 작업 · 2026년 10월 10일 기준 · 팀 공유용

현재 단계: macOS 앱에서 로컬 영상을 재생하고, 사건 정보와 분석 목적을 바탕으로 계획을 승인한 뒤 로컬 VLM이 후보를 표시합니다. 대표 택배 영상에서 실제 모델 응답과 원본 시점 이동을 확인했습니다. 여러 영상에 대한 탐지 정확도 검증과 PDF 검색 연결은 다음 단계입니다.

1. 어디까지 끝났나

영역현재 상태와 확인 범위
앱과 영상Python 3.13·PySide6 macOS 데스크톱 앱. 로컬 파일 선택, 영상 재생, 메타데이터 확인, 후보 클릭 시 원본 시점 이동을 구현했습니다.
분석 흐름목적 입력 → 필요한 추가 질문 → 계획 제시 → 사용자 승인 → 백그라운드 분석 → 후보·근거·불확실성 표시. 입력이 바뀌면 승인을 다시 받습니다.
실제 로컬 모델Ollama의 qwen3-vl:4b-instruct, qwen3-vl:8b-instruct를 연결했습니다. 알려진 몇 개 영상에서 실제 응답과 후보 표시를 확인했습니다. 후보 없음·일부 분석·오류도 별도 상태입니다.
사건 정보사건 관리 정보와 분석에 쓸 사전 단서를 분리했습니다. 단서마다 출처·확실성·사용 여부를 저장하고, 선택한 단서만 계획·모델 입력·결과 기록에 포함합니다.
외부 APIOpenAI 호환 요청 구성, 키 입력, 이미지 입력 확인, 별도 전송 승인을 구현했습니다. 실제 과금 API 호출은 아직 검증하지 않았습니다.
PDF·데이터PDF 검색의 공통 형식과 자료 없음 상태만 준비했습니다. VS9/VL9 파일 구조·MP4–JSON 대응 조사는 아직 완료되지 않았습니다.
검증·패키징자동 테스트 122개 통과. 개발용 .app 빌드와 offscreen 실행 확인. 서명·공증 및 다른 Mac에서의 설치 검증은 남았습니다.

2. 승재가 지금까지 한 작업

  • 공통 구조: 분석 요청·작업·구간·근거·오류·출처 계약, 샘플/로컬/외부 모델 공통 인터페이스, 실행 진입점과 개발용 패키징.
  • 영상 처리: FFprobe 메타데이터, 원본 기준 초와 디코딩 타임스탬프(PTS), 제한된 프레임 추출. 가변 프레임률을 FPS만으로 환산하지 않습니다.
  • 후보 제안: FFmpeg 픽셀 변화로 움직임 구간을 제안하고 최대 3개를 분석 계획에 등록합니다. 이 점수는 행동 확률이나 범죄 판단이 아닙니다.
  • Agent: 부족한 정보가 있을 때 질문하고, 대상·범위·샘플링·시간·프레임·모델 요청 한도를 계획에 표시합니다. 승인 전 실행을 막고 변경 시 승인을 무효화합니다.
  • 실제 분석: 원본 시각과 프레임을 VLM에 보내고 JSON·근거 프레임·시간 범위를 검증합니다. 관찰 내용, 근거, 불확실성을 함께 표시하고 원본 확인 범위를 구분합니다.
  • 안정성: 백그라운드 실행, 중복 실행 차단, 취소 뒤 늦은 결과 무시, 전체 300초 예산과 12프레임·최대 3요청 한도, 결과·설정의 사용자 데이터 폴더 저장.
  • 사건 맥락: CaseRecord와 AnalysisClue를 저장하고 사전 정보가 영상 관찰 사실이 아님을 프롬프트에 명시합니다. 외부 전송 시 단서 문구도 별도 승인 화면에 표시합니다.

3. 대표 택배 영상에서 확인한 것

최근 비교에 사용한 파일은 C041_A30_SY32_P07_S06_01DAS.mp4(영상 ID 6abc166c16bc5f57)입니다. 처음 공유했던 …S05_03DAS.mp4와 다른 파일이므로 결과를 합치지 않습니다. 같은 영상·목적·8B 모델·균등 표본 12프레임으로 두 번 실행했습니다.

조건실행 결과해석
사전 단서 사용12/12프레임, 후보 2개약 01:05–01:15, 01:25–01:45. 결과에 사전 단서의 색상·인물 표현이 나타나 문구 영향 가능성이 있습니다.
사전 단서 제외12/12프레임, 후보 3개약 00:05–00:35, 00:55–01:05, 01:25–01:45. 첫 항목은 “상자가 그대로 있다”는 내용이라 상자 이동 목적에 맞지 않는 후보입니다.

모델 후보는 사람이 원본에서 확인해야 합니다. 12개의 듬성듬성한 프레임으로 행동 시작·종료를 정확히 측정하거나 절도 성립·사람의 의도를 확정할 수 없습니다. 위 두 실행만으로 사전 정보가 탐지 성능을 높였다고 판단할 수 없습니다.

4. 앞으로 남은 작업 — 승재 담당

우선순위작업완료 기준
먼저목적과 무관한 후보를 결과에서 구분하는 검증·후처리 보완. 택배 영상 00:05–00:35 같은 사례를 재현 자료로 사용.상자가 그대로 있는 장면을 “상자 이동 후보”로 단정하지 않고, 제외 또는 추가 확인 상태와 이유를 남깁니다. 실제 관련 장면은 과도하게 버리지 않는지도 확인합니다.
먼저사람의 후보 확인 결과를 저장할 공통 형식 합의 및 연결. 누나의 검토 UI와 경계를 맞춥니다.후보별 관련 있음·제외·추가 확인, 메모, 확인자·시각, 원본 근거가 저장·재열람됩니다. AI 원결과는 덮어쓰지 않습니다.
다음여러 영상의 블라인드 평가 절차와 간단한 측정표 구축.모델 입력에서 라벨을 분리한 채 미탐지·오탐지·근거 시각·처리 시간을 영상별로 기록합니다. 알려진 한 영상의 성공을 일반 정확도로 쓰지 않습니다.
다음모델 오류·취소·서버 작업 잔존 및 8B 실행 시간 점검.부분 결과와 실패 원인이 구분되고 취소 후 새 요청이 서버 작업과 겹치지 않음을 확인합니다.
후속 결정외부 API 실제 연결, 개발용 앱의 다른 Mac 검증, 정식 배포 정책.사용자가 비용·전송 범위를 정한 뒤 최소 실제 호출을 확인합니다. 서명·공증은 별도 결정합니다.

6. 누나가 작업을 시작하는 방법

코드는 GitHub 저장소의 codex/local-vlm-ollama 브랜치(fd529c6)에 공유됐습니다. 자료는 Google Drive 공유 폴더에서 직접 확인합니다. Drive 파일 목록은 이 문서 작성 시 자동 확인하지 못했으므로 실제 존재하는 자료를 먼저 기록해야 합니다.

git clone https://github.com/AI-Agent-Jeong-Oh/AI_Agent.git
cd AI_Agent
git switch codex/local-vlm-ollama
git switch -c feature/team-ui-knowledge
./scripts/bootstrap_macos_dev.sh --check-only
./scripts/bootstrap_macos_dev.sh --dev
QT_QPA_PLATFORM=offscreen PYTHONPATH=src ./.venv/bin/python -m unittest discover -s tests -q
PYTHONPATH=src ./.venv/bin/python -m video_agent

스크립트는 FFmpeg·Ollama·모델을 자동 설치하지 않습니다. 영상·ZIP·라벨 JSON·모델 가중치·API 키·개인 분석 결과는 저장소 밖에 두고 Git에 올리지 않습니다.

7. 두 사람이 맞춰 볼 첫 통합 완료선

  1. 사건을 만들고 분석에 사용할 단서를 선택·저장한 뒤 앱을 재시작해 다시 불러올 수 있습니다.
  2. 택배 영상에서 목적·범위·모델·단서가 계획에 표시되고, 변경하면 재승인을 요구합니다.
  3. 로컬 VLM 결과에는 관찰·근거 원본 시각·불확실성이 표시됩니다. 후보 없음과 일부 완료도 올바르게 보입니다.
  4. 사람이 각 후보를 확인하고 관련성 판단을 AI 원결과와 별도로 남길 수 있습니다.
  5. PDF 검색기가 연결되면 문서·페이지·자료 버전을 확인할 수 있고, 자료가 없으면 명확히 미연결로 표시됩니다.
