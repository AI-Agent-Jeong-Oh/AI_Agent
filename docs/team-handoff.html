영상 데이터 중요 구간 선별 Agent

팀원 개발 시작 안내 · macOS / PySide6 / 로컬 우선

목표: 팀원이 사건 입력 UI, PDF 검색, 데이터 조사와 사용성 검증을 기존 분석 엔진에 안전하게 연결한다.

1. 시작 전에 알아둘 기준

이 문서의 사건 유형이나 신고 내용은 관리·탐색용 정보입니다. 데이터셋 폴더명과 정답 라벨 JSON을 VLM 입력에 넣거나 모델 관찰 결과로 바꾸지 않습니다.
  • 앱은 웹 업로드가 아닌 로컬 파일 경로를 읽는 PySide6 데스크톱 앱입니다.
  • 로컬 모드 실패 시 외부 API나 샘플 결과로 자동 전환하지 않습니다.
  • 사건명·담당자 같은 관리 정보와 모델에 보내는 분석 단서를 구분합니다.
  • 실제 영상·ZIP·JSON 라벨·API 키·모델·개인 분석 결과는 Git에 올리지 않습니다.
  • 공통 계약이나 main_window.py를 바꾸기 전에 승재와 변경 범위를 합의합니다.

2. 자료와 코드 받기

구분위치사용 원칙
공유 자료 Google Drive 공유 폴더 접근 권한과 실제 파일 목록을 직접 확인합니다. 영상·ZIP은 저장소 밖의 개인 데이터 폴더에 둡니다.
소스 코드 GitHub 저장소 codex/local-vlm-ollama 공유 브랜치를 받은 뒤 본인 기능 브랜치를 만듭니다. main에 바로 작업하지 않습니다. 
git clone https://github.com/AI-Agent-Jeong-Oh/AI_Agent.git
cd AI_Agent
git status
git branch --all
git switch codex/local-vlm-ollama
git pull --ff-only
git switch -c feature/case-ui-pdf-search

팀원은 공유 브랜치의 최신 커밋에서 사건·사전 정보 연결 코드와 이 안내 문서를 확인한 뒤 작업을 시작합니다.

Google Drive 폴더는 작성 시점에 자동 열람으로 파일 목록을 확인하지 못했습니다. 팀원이 브라우저에서 권한과 파일명을 직접 확인하고, “확인한 것”과 “아직 없는 것”을 구분해 기록합니다.

3. macOS 개발 환경 준비

스크립트는 프로젝트 안의 .venv만 만들며 시스템 Python, 보안 설정, Ollama 모델을 자동 변경하지 않습니다.

./scripts/bootstrap_macos_dev.sh --check-only
./scripts/bootstrap_macos_dev.sh --dev
PYTHONPATH=src ./.venv/bin/python -m video_agent

필수 기준은 Python 3.13.x, PySide6 6.12.0입니다. 영상 메타데이터·프레임 기능에는 FFmpeg/FFprobe가 필요합니다. 실제 로컬 VLM 검증에는 Ollama와 팀에서 합의한 비전 모델이 별도로 필요하며 모델은 자동 다운로드하지 않습니다.

QT_QPA_PLATFORM=offscreen PYTHONPATH=src \
  ./.venv/bin/python -m unittest discover -s tests -v

4. 현재 연결된 사건 정보 계약

정의 위치: src/video_agent/contracts.py. 저장 위치: macOS 사용자 데이터 폴더의 VideoAnalysisAgent/cases/.

{
  "case_id": "case-...",
  "revision": 1,
  "title": "문 앞 택배 이동 확인",
  "case_type": "관리용 분류",
  "occurrence_time_text": "발생 시각 미확인",
  "occurrence_time_certainty": "unknown",
  "management_notes": "모델에 전송하지 않는 관리 메모",
  "clues": [{
    "clue_id": "clue-...",
    "text": "신고자는 문 앞 물체가 이동했다고 설명함",
    "source": "report",
    "certainty": "estimated",
    "use_for_analysis": true
  }],
  "video_links": [{
    "video_id": "경로가 아닌 영상 식별 해시",
    "camera_location": "공동현관 앞",
    "clock_offset_seconds": 0.0,
    "clock_certainty": "unknown"
  }]
}
  • title, case_type, management_notes는 관리용이며 모델에 보내지 않습니다.
  • use_for_analysis=true인 단서만 승인 계획과 VLM 프롬프트에 포함됩니다.
  • 모델 프롬프트는 단서를 “영상 관찰 사실이 아닌 사용자 제공 정보”로 표시합니다.
  • 단서·사건 버전이 바뀌면 기존 분석 승인을 재사용하지 않습니다.
  • 외부 API 계획에는 전송할 단서 문구를 그대로 표시하고 별도 전송 승인을 요구합니다.
  • 카메라 시각 오차는 사건 메타데이터입니다. 원본 영상 경과 초와 프레임 PTS를 다시 쓰지 않습니다.

5. 팀원이 이어서 할 작업

작업수정 시작 위치완료 기준
사건 입력 UI와 사용성 src/video_agent/ui/case_panel.py 관리 정보와 분석 단서가 명확히 구분되고, 단서별 출처·확실성·분석 사용 여부를 조작할 수 있다.
PDF 전처리·검색 src/video_agent/knowledge/contracts.py 문서 ID·문서명·페이지·자료 버전·발췌문을 반환한다. 자료가 없으면 미연결 상태이며 가짜 출처를 만들지 않는다.
VS9/VL9 데이터 조사 새 조사 문서와 독립 스크립트 실제 파일이 있을 때만 MP4/JSON 구조와 대응 규칙을 기록한다. 정답 라벨은 분석 입력에 넣지 않는다.
사람 검토 UI src/video_agent/ui/의 별도 위젯 제안 후보에 관련 있음/제외/추가 확인과 메모를 남기고 원본 시점으로 이동한다.
사용성·수동 검증 docs/ 검증 기록 자동 테스트, 화면 수동 확인, 실제 모델 호출을 구분해 기록한다.
첫 통합 완료선: 사건 정보 + 텍스트 단서 → 추가 질문 → 계획 승인 → 로컬 VLM 분석 → 원본 검토 → 저장. 후보가 없어도 빈 결과로 정상 종료되어야 합니다.

6. 대표 사례 사용 방법

대표 파일명은 C041_A30_SY32_P07_S05_03DAS.mp4입니다. 파일 경로나 분류 폴더명은 모델 입력에 사용하지 않습니다.

  1. 사건명: 문 앞 택배 이동 확인
  2. 목적: “사람이 문 앞의 상자를 들어 다른 위치로 이동시키는 것으로 보이는 장면 후보 찾기”처럼 관찰 가능한 행동으로 작성
  3. 사전 단서: 사용자가 실제 제공한 신고·진술만 추가하고 출처와 확실성을 표시
  4. 모델 결과의 상자 위치·손의 접촉·이동 전후 시각을 원본에서 사람이 확인
  5. 영상만으로 절도 성립이나 사람의 의도를 확정하지 않음

7. 변경 공유 체크리스트

  • git status와 git diff에서 영상·키·개인 경로가 없는지 확인
  • 관련 테스트를 실행하고 실제 실행하지 않은 항목은 미검증으로 표시
  • 공통 계약을 바꾸면 docs/contracts.md와 테스트를 같이 변경
  • 기능 브랜치에 의도한 파일만 커밋하고 원격 push/PR은 팀 합의 후 수행
  • 승재에게 입력·출력 예시, 변경 파일, 검증 결과, 남은 문제를 전달
