# 현재까지 구현 기록

기록일: 2026-10-10

이 문서는 앞으로 할 일을 정하는 계획서가 아니라, 현재 저장소에 무엇을 어떤 방식으로 구현했고 어디까지 실제로 확인했는지를 설명하는 기록입니다.

가장 최근에는 사건 정보와 사전 단서 계약을 추가했습니다. 사건명·유형·발생 시각 확실성·관리 메모와 영상 식별자·카메라 시각 오차를 `CaseRecord`로 저장하며 원본 경로는 저장하지 않습니다. 단서마다 출처·확실성·분석 사용 여부를 두고 선택된 단서만 계획 fingerprint, 분석 요청, 결과 JSON과 VLM 프롬프트에 포함합니다. 프롬프트 버전은 `candidate-recall-v10-prior-context-separated`이며 사전 정보를 영상 관찰 사실로 가정하거나 그대로 복사하지 않도록 분리했습니다. 이 연결은 자동 테스트와 오프스크린 UI 및 대표 택배 영상의 실제 8B 모델 비교 두 건으로 확인했습니다. 비교 결과와 한계는 아래와 `docs/handoff-seungjae.md`에 기록했습니다.

그 이전에는 손가락·초인종 버튼·누르기·접촉처럼 작은 대상이 핵심인 목적에서 최대 1920px 원본을 추출하고, 각 원본 시각의 전체 화면 보기와 중앙 60% 확대 보기를 1280×1080 한 장에 구성하도록 분기했습니다. 당시 프롬프트는 `candidate-recall-v9-overview-detail-crop`이며 같은 시각의 두 보기를 하나의 근거로 취급하고 압력·작동 여부를 단정하지 않습니다. 직전 수동 v9 결과의 영상 ID를 대조해 유모차 영상에 초인종 목적을 적용한 불일치를 발견했고, 해당 빈 결과는 초인종 탐지 성능 근거에서 제외했습니다. 올바른 초인종 영상 ID `7b9f9a0a3ba37350`의 97~99.5초를 4B로 다시 실행한 기준선은 47.214초, `completed`, `real_model`, 10/10프레임, 배치별 후보 `(0, 0, 0)`이었습니다. 같은 입력의 8B thinking 태그는 첫 요청이 67.674초 뒤 최종 content 없이 thinking만 반환해 명시적으로 실패했습니다. 사용자 승인으로 별도 설치한 `qwen3-vl:8b-instruct`는 동일 입력 3요청을 110.743초에 모두 검증했고, 배치별 후보 `(1, 1, 1)`과 97.130~99.399초 근거를 반환했습니다. 이는 초인종 장치와 손가락의 근접 후보이며 실제 누름·작동 판정이나 일반 정확도 검증은 아닙니다.

## 전체 요약

Python과 PySide6를 사용해 macOS에서 실행되는 영상 중요 구간 선별 데스크톱 앱의 초기 기반을 만들었습니다. 사용자는 로컬 영상 파일을 선택하고, 분석 목적과 시간 범위를 입력하고, 표시된 분석 계획을 승인한 뒤 샘플 중요 구간을 확인할 수 있습니다. 후보를 선택하면 원본 영상의 해당 시작 시점으로 이동합니다.

기본 모드는 영상 내용을 해석하지 않는 샘플 결과입니다. 별도로 Ollama와 `qwen3-vl:4b-instruct`를 설치해 실제 로컬 이미지 입력 호출과 계약 변환까지 확인했습니다. 전체 범위의 희소 프레임에서 놓친 짧은 행동을 위해 로컬 움직임 제안과 촘촘한 후속 분석을 추가했습니다. 제공 영상에서는 92~98초가 최상위로 제안됐고 실제 모델 후보도 생성됐지만, 개발자가 시각을 이미 알고 있던 단일 영상이므로 정확도 검증으로 간주하지 않습니다.

후속으로 목적별 샘플링을 추가했습니다. 두리번거림·주변 살피기·반복 방향 변화 목적은 160px 회색조의 8×5 타일에서 국소 변화를 계산하고, 한 번의 큰 변화보다 시간 동안 분산된 변화를 우선하는 별도 프로필을 사용합니다. 제공 영상의 전처리 확인에서는 63~73초, 78.5~88.5초, 88.5~98.5초가 상위 3개로 제안됐습니다. 이는 사용자가 알려 준 구간과 겹치는 로컬 전처리 결과이며 실제 VLM의 새 프롬프트 탐지 성공은 아직 확인하지 않았습니다.

## 구현한 사용자 흐름

다음 순서가 하나의 앱 안에서 이어지도록 구성했습니다.

```text
로컬 영상 선택
→ 영상 재생 및 메타데이터 확인
→ 분석 목적과 원본 시간 범위 입력
→ 선택적으로 로컬 움직임 후보 탐색·범위 적용
→ 필요한 경우에만 추가 질문
→ 분석 계획 표시
→ 사용자 승인
→ 백그라운드 분석
→ 중요 구간 후보 표시
→ 후보 클릭 시 확인용 범위 최대 1초 전부터 원본 맥락 재생
```

외부 API 모드에서는 분석 계획 승인만으로 실행되지 않습니다. 공급자, 목적지, 전송할 목적 텍스트와 JPEG 프레임 시각을 표시한 뒤 외부 전송을 별도로 승인하도록 분리했습니다.

오른쪽 분석 패널은 세로 스크롤로 전체 단계에 접근하며, 움직임 변화 제안 목록과 분석 계획 본문에 최소 높이를 두어 섹션이 한두 줄로 눌리지 않게 했습니다. 상단 버튼과 `⌘+`, `⌘-`, `⌘0`으로 75~150% UI 확대·축소가 가능합니다. 움직임 후보는 체크박스, `n/3` 카운터, 선택 시간 목록과 개별·전체 해제 버튼으로 선택 상태를 명시합니다.

짧은 실제 모델 후보도 원본 맥락을 확인하기 쉽도록 결과 항목에는 모델의 확인용 재생 범위와 관찰 PTS를 그대로 표시하고, 클릭 시에는 그 범위 시작의 최대 1초 전으로 이동합니다. 재생은 범위 뒤에도 계속되며, 추가된 여유 시간은 모델 근거나 저장 결과로 취급하지 않습니다.

## 영상 처리 구현 방식

- FFprobe로 영상 길이, 해상도, 평균·명목 FPS, 회전, codec, 오디오, 시작 시각과 timebase를 읽습니다.
- 앱 내부의 공통 시간은 원본 시작 기준 초 단위로 유지합니다. Qt 재생기와 연결되는 경계에서만 밀리초로 변환합니다.
- 가변 프레임률 영상의 시각을 프레임 번호를 FPS로 나누어 계산하지 않습니다.
- FFmpeg로 계획에 포함된 시각의 프레임만 제한적으로 추출합니다. 영상 전체를 메모리에 올리지 않습니다.
- 별도 움직임 탐색은 일반 목적에서 320px 이하 전체 화면 변화의 비중첩 6초 구간을, 반복·미세 목적에서 160px 회색조 타일 변화의 비중첩 10초 구간을 최대 5개 제안합니다. 둘 다 최대 600개의 PTS 기반 표본으로 제한하며 점수는 행동 확률이나 이상 판정이 아닙니다.
- 추출 결과에는 요청한 시각과 FFmpeg `showinfo`에서 확인한 실제 decoded PTS를 함께 기록합니다.
- 원본 영상은 수정하지 않으며 한글과 공백이 포함된 경로도 처리합니다.
- FFmpeg와 FFprobe는 shell을 통하지 않고 실행하며 취소나 시간 초과 시 하위 프로세스 그룹을 정리합니다.

## Agent와 승인 구현 방식

- 목적이 너무 짧거나 일반적일 때만 판단 기준을 묻는 추가 질문을 만듭니다.
- 지속 시간이 핵심인 목적에 초·분 기준이 없으면 시간 기준을 추가로 묻고 계획 목적에 포함합니다.
- 두리번거림·주변 살피기·반복 방향 변화 목적은 관찰 가능한 머리·얼굴·몸통 방향 비교 기준과 `temporal_sequence` 전략을 계획에 포함합니다.
- 분석 계획에는 영상, 목적, 모드, 모델, 시간 범위, 샘플 시각, 실행 시간과 프레임 한도가 포함됩니다.
- 계획 내용으로 fingerprint를 만들기 때문에 영상·목적·모델·범위·공급자 설정이 바뀌면 기존 승인이 무효화됩니다.
- 승인 전에는 분석 요청을 만들 수 없습니다.
- 기본 실행 한도는 계획당 1회이며 자동 재분석과 공급자 자동 재시도는 사용하지 않습니다.
- 분석 범위를 넓혀야 하는 경우 자동으로 실행하지 않고 제안 상태로만 남깁니다.
- 움직임 후보를 적용하면 범위·샘플링 변경으로 기존 승인이 폐기되며, 새 계획을 승인하기 전에는 VLM을 호출하지 않습니다. 일반 프로필은 변화 정점 주변, 반복·미세 프로필은 선택 구간 전체에 총 12프레임을 나눠 배정합니다.
- 취소한 작업의 늦은 진행 이벤트나 결과가 현재 화면을 덮어쓰지 못하도록 작업 ID를 확인합니다.
- 로컬 12프레임은 시간순 4개씩 최대 3회 요청하고, 프레임 추출부터 모든 응답 검증까지 하나의 300초 예산을 사용합니다.

## 분석기와 모델 연결 구조

분석기는 다음 세 종류를 구분합니다.

| 구분 | 현재 구현 |
|---|---|
| `sample` | 프레임을 해석하지 않고 승인 범위의 길이 비율로 후보 생성 |
| `local` | loopback 주소의 명시된 영상 입력 모델에 연결하는 어댑터 |
| `external` | HTTPS 외부 API에 별도 전송 승인 후 연결하는 어댑터 |

외부 모드에는 OpenAI 기본 endpoint와 암호형 API 키 입력을 연결했습니다. 화면에서 입력한 키는 현재 실행 메모리와 인증 헤더에만 사용하고 설정·결과·로그에는 저장하지 않습니다. `OPENAI_API_KEY` 환경 변수도 지원하며, 사용자가 이미지 입력 지원 모델임을 명시적으로 확인해야 계획을 만들 수 있습니다. 분석 승인과 전송 범위 승인은 계속 분리되고 키가 없으면 실행할 수 없습니다. 가짜 공급자로 요청 구성과 키 미저장을 검증했으며 실제 OpenAI 과금 호출은 아직 수행하지 않았습니다.

샘플 분석기와 실제 모델 분석기를 별도 클래스로 구성했습니다. 로컬 모델 연결에 실패해도 외부 API나 샘플 결과로 자동 전환하지 않습니다.

모델에는 승인된 시각에서 추출한 JPEG 프레임, 각 프레임의 원본 시각과 사용자 목적을 전달하도록 구성했습니다. 모델 응답은 다음 내용을 검사합니다.

- JSON 최상위 형식과 필수 필드
- 구간 시작과 종료 순서
- 승인된 분석 범위와 원본 영상 길이
- 실제 입력으로 전달한 frame ID인지 여부
- 확인용 재생 범위가 실제 근거 프레임 원본 시각을 포함하는지 여부. 승인 범위 안에서 이 조건만 어긴 경우 근거 앞뒤 1초로 대체하고 보정 사실을 불확실성에 기록
- 요약, 관찰 근거와 불확실성 존재 여부
- 관찰 근거 칸에 frame ID만 복사하지 않았는지 여부
- 범죄 성립이나 사람의 의도를 확정하는 일부 위험 표현

승인 범위 초과·역전 구간은 거부하고 실패 결과를 샘플 결과로 바꾸지 않습니다. 확인용 범위의 근거 포함 보정은 원래 값과 이유를 결과에 명시합니다. 여러 배치에서 관찰 요약이 같고 확인 범위가 겹치며 근거 시각이 1초 이내인 후보만 중복 표시로 묶고 모든 원래 근거와 묶음 사실을 유지합니다. 테스트의 가짜 공급자 응답도 실제 모델 결과와 다른 `test_double` 출처로 표시합니다.

## 실행 안정성과 저장

- 메타데이터 확인과 분석을 Qt 백그라운드 작업으로 실행해 UI 이벤트 처리를 막지 않습니다.
- 중복 실행, 취소, 시간 초과, 손상 영상, 지원하지 않는 확장자와 잘못된 모델 응답을 오류 상태로 처리합니다.
- 실제 진행률을 알 수 없는 단계는 숫자를 추정하지 않고 불확정 진행 상태로 표시합니다.
- 불확정 단계는 진행 단계와 실제 경과 시간을 표시하며, 취소 뒤 worker가 끝날 때까지 새 요청을 막습니다.
- `completed` 빈 결과, `partial`, `failed`, `canceled`를 구분하고 취소 결과는 저장하지 않습니다.
- 설정과 결과는 `~/Library/Application Support/VideoAnalysisAgent`에 저장합니다.
- 추출 프레임 캐시는 `~/Library/Caches/VideoAnalysisAgent`에 저장합니다.
- 결과 JSON에는 원본 영상 경로를 넣지 않고 API 키 값도 저장하지 않습니다. 영상 ID, 목적·범위, 실제 입력 프레임 ID·시각·해상도, 모델 설정, 요청 수와 실행 시간은 저장합니다.
- 실제 모델 결과에는 후보 선별 프롬프트 버전과 완료 배치별 원시 후보 수도 저장합니다. 후보 수는 정확도나 확률이 아닙니다.
- 앱 소유 marker가 있는 캐시 폴더만 정리할 수 있도록 제한했습니다.

## PDF 연결 계약

PDF 추출이나 검색 자체는 구현하지 않았습니다. UI와 검색 코드가 나중에 같은 형식으로 연결될 수 있도록 검색 질의와 결과 계약을 만들었습니다. 결과에는 본문, 문서 ID, 문서명, 페이지, 자료 버전과 선택적인 검색 점수·임베딩 모델 정보를 담을 수 있습니다.

자료나 검색기가 없는 현재 상태에서는 가짜 출처를 만들지 않고 `PDF 지식 자료 없음/검색기 미연결`을 반환합니다.

## 개발용 패키징

PyInstaller 설정과 빌드 스크립트를 작성해 `dist/VideoAnalysisAgent.app`을 만들었습니다. 확인한 번들은 arm64, 약 113MB이며 bundle identifier는 `org.ai-agent-jeong-oh.video-analysis-agent.dev`입니다.

이 번들은 개발 확인용 ad-hoc 서명 상태입니다. 모델 가중치, 원본 영상, API 키와 Homebrew FFmpeg는 포함하지 않았습니다.

## 2026-10-10 반복·미세 변화 후속

- 두리번거림·주변 살피기 같은 목적은 전체 화면 평균 대신 8×5 국소 타일 변화가 10초 구간에 분산되는 정도를 우선하는 전처리와 `temporal_sequence`를 사용합니다. 제공 영상에서 63~73초와 78.5~88.5초가 상위 제안에 포함됐지만 이는 행동 인식이나 정확도 결과가 아닙니다.
- 로컬 모드에서 시간순 원본 프레임 최대 4개를 FFmpeg로 최대 2×2 비교 보드 한 장에 구성하는 경로를 추가했습니다. 공급자 입력은 한 이미지지만 원본 frame ID·decoded PTS는 응답 검증과 저장에 유지하고, `provider_image_count`, `provider_image_dimensions`, `input_representation`으로 두 입력 층을 구분합니다. 외부 모드는 전송 승인 내용과 실제 payload를 일치시키기 위해 개별 프레임을 유지합니다.
- `qwen3-vl:4b-instruct`에 64.2642·66.7667·69.2692·71.7717초 원본 프레임 4개를 비교 보드 한 장으로 전달한 정식 v6 검증은 5.245초에 `completed`, `real_model`, 4/4프레임으로 끝났으나 후보는 0개였습니다. 연결 성공이지 탐지 개선 성공은 아닙니다.
- 더 단순한 비교 보드 진단 프롬프트에서는 방향 변화 후보 문장이 생성됐지만 관찰 근거 형식이 앱 계약을 충족하는지 검증하지 않았으므로 실제 앱 후보 성공으로 세지 않습니다.
- 당시 `candidate-recall-v7-temporal-panel-checklist`는 빈 배열을 결정하기 전 패널별 방향을 비교하도록 간결하게 정리했습니다. 실제 요청 한도를 소진한 뒤 작성되어 자동 테스트만 통과했으며 실제 4B/8B 탐지는 미검증입니다. 현재 프롬프트 버전은 v9 전체 화면+중앙 확대 정밀 접촉 분기입니다.
- 단일 92~98초 프레임 접촉표에서는 사람과 유모차의 자세가 유사하고 다리·접촉 부위가 부분적으로 가려져 있어, 빈 결과 원인을 프롬프트 하나로 단정할 수 없었습니다. 후속 다중 후보 계획은 실제 영상의 상위 3개 `92~98`, `107~113`, `114~120초`에서 변화 정점 주변 4장씩 총 12장을 960×540으로 추출했습니다. 요청 시각과 decoded PTS를 확인했으며 모델 호출은 추가하지 않았습니다.

실제 모델의 요청·응답·계약·빈 결과와 촘촘한 후보 결과 저장을 검증했고, 새 `.app`에서 8B instruct 후보 표시·원본 seek도 사용자가 수동 확인했습니다. 다만 이 후보들은 시각을 이미 아는 단일 개발 영상에서 얻었으므로 CCTV 행동 탐지 성능이나 일반 정확도 검증은 아닙니다. 외부 VLM, 블라인드 다중 영상 정확도, 인증서 서명·공증은 미검증입니다.
