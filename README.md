# 영상 데이터 중요 구간 분석 Agent

PC의 로컬 영상에서 사용자 목적에 맞는 중요 구간 후보를 만들고 원본 시점에서 확인하는 macOS 데스크톱 앱입니다. 처음 실행할 때 이 컴퓨터에 영상 입력이 확인된 Ollama 비전 모델이 있으면 로컬 분석(`빠른 분석`)으로 시작하고, 없으면 **시연용(실제 AI 분석 아님)** 으로 시작합니다. 로컬 분석이 실패해도 외부 API나 시연용 결과로 자동 전환하지 않습니다. 분석 뒤에는 사람이 후보마다 판단·메모를 기록하고, 그 기록으로 만든 결과 요약 초안을 HTML로 내보낼 수 있습니다.

## 구현 상태

- 사건명·유형·발생 시각 확실성·관리 메모와 영상 연결 정보를 사용자 데이터 폴더에 버전 저장
- 사전 단서별 출처·확실성·분석 사용 여부를 구분하고, 선택 단서만 계획·VLM 입력·결과 출처에 보존
- 사전 정보 변경 시 기존 승인 무효화, 외부 모드에서는 전송할 단서 문구까지 별도 승인 화면에 표시
- 로컬 파일 선택, 영상 재생, 원본 타임라인 탐색
- FFprobe 기반 길이·해상도·평균/명목 FPS·회전·오디오·timebase 확인
- FFmpeg로 승인된 원본 시각의 프레임만 제한 추출하고 디코딩 PTS 기록
- FFmpeg 저해상도 전처리로 일반 목적은 큰 변화 6초 구간, 두리번거림·반복 방향 변화 목적은 국소 변화가 이어지는 10초 구간을 최대 5개 제안
- 선택한 최대 3개 구간을 목적에 따라 변화 정점 주변 또는 구간 전체 시간순으로 총 12프레임 안에서 재계획
- 목적이 모호할 때만 추가 질문 → 계획 → 분석 승인 → 실행 → 결과 검증
- 목적·영상·모델·범위 변경 시 승인 무효화
- 외부 API의 분석 승인과 전송 내용·범위 승인을 별도 처리
- 샘플/테스트 가짜 응답/실제 모델 결과 출처 구분
- 백그라운드 메타데이터·분석 작업, 취소, 시간·프레임·실행 횟수 제한
- macOS 사용자 데이터 폴더에 설정·결과·캐시 분리 저장
- 로컬/외부 VLM HTTP 어댑터와 엄격한 JSON 응답 검증
- 로컬 12프레임을 시간순 4개씩 처리하는 제한 배치와 300초 공통 실행 예산
- 미세·반복 방향 변화 목적에서 원본 4프레임을 최대 2×2 시간순 비교 보드 한 장으로 묶는 입력 방식과, 손가락·버튼·접촉 목적에서 전체 화면과 중앙 60% 확대 보기를 함께 제공하는 정밀 입력 방식
- 프레임 ID만 복사한 관찰 근거 거부와 동일 요약·인접 근거 후보의 보수적 중복 정리
- 프롬프트 버전과 배치별 원시 후보 수를 결과에 기록해 빈 결과와 중복 정리 과정을 구분
- 후보 없음·일부 배치 완료·실패·취소를 구분하고 실제 입력 시각·실행 지표 저장
- 팀원 구현용 PDF 검색 계약과 “자료 없음/미연결” 기본 구현
- 서명·공증 없는 개발용 macOS `.app` 빌드 설정
- 오른쪽 패널을 `① 사건 등록` → `② 영상 분석` → `③ 결과 검토` 3단계 화면으로 나누고, 단계 표시줄과 이전·다음 버튼으로 자유롭게 이동
- 후보 검토 패널: 후보 목록·선택 구간 상세·수사관 기록(관련 있음/추가 확인/제외, 메모, 태그, 북마크), 검토 상태 필터·정렬, `구간만`/`전후 30초`/`전후 2분` 범위 재생
- 사건 유형(실종·폭행·아동학대·기타)에 따라 `중점 관찰 항목`을 추천·체크하고, 체크한 상황과 직접 입력한 짧은 힌트를 계획의 관찰 기준으로 모델에 전달(확인 순서에만 반영)
- `분석 방식` 한 가지 선택: `빠른 분석`·`정확한 분석`(이 컴퓨터의 모델, 크기 순)·`시연용`·`외부 AI 분석`. 클라우드 모델은 로컬 분석에서 제외
- 분석 결과의 후보 구간을 재생 막대에 판단별 색으로 표시하고, 표시를 누르면 해당 후보로 이동
- 검토 기록을 분석 결과와 별도 파일로 저장·복원하고, 저장된 결과를 다시 열기. 저장하지 않은 기록이 있으면 닫기·다른 영상·새 분석·다른 결과 전에 확인
- `분석 완료`로 미검토·미저장 항목을 경고한 뒤 완료 시각 기록
- 사람 확인 시간을 앱이 활성 상태일 때만 측정해 검토 기록 파일에만 저장(화면·요약에는 표시하지 않음)
- 결과 요약 6개 영역 초안(AI 호출 없음, 문구 편집 가능)과 HTML 내보내기
- 결과 요약 ⑤에 영상 증거 처리 공통 규정 7개의 제목과 국가법령정보센터 링크 표시. 사건별 참고 법령은 미연결

## 개발 환경

- 기준 OS: macOS 26.6.2, Apple Silicon
- Python: 3.13.x
- PySide6 Essentials/Addons: 6.12.0
- FFmpeg/ffprobe: 개발 PC에서 8.1.2로 검증
- PyInstaller: 6.22.3, 개발 패키징에만 사용

Qt 공식 설치 문서는 Python 3.10 이상과 가상환경을 권장합니다. PySide6 6.12.0과 PyInstaller 6.22.3의 macOS universal2 배포본은 Python 3.13과 arm64를 지원합니다.

## 설치와 실행

FFmpeg가 없다면 먼저 설치하고 `ffprobe`, `ffmpeg`가 실행되는지 확인합니다. 앱은 PATH 외에도 Apple Silicon/Homebrew의 `/opt/homebrew/bin`과 Intel Homebrew의 `/usr/local/bin`을 확인합니다.

```bash
git clone https://github.com/AI-Agent-Jeong-Oh/AI_Agent.git
cd AI_Agent
git switch codex/local-vlm-ollama
python3.13 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
PYTHONPATH=src ./.venv/bin/python -m video_agent
```

새 팀원은 시스템 설정이나 모델을 자동 변경하지 않는 준비 스크립트를 사용할 수 있습니다.

```bash
./scripts/bootstrap_macos_dev.sh --check-only
./scripts/bootstrap_macos_dev.sh --dev
PYTHONPATH=src ./.venv/bin/python -m video_agent
```

VS Code에서는 `.venv/bin/python`을 interpreter로 선택합니다. 앱은 선택한 원본을 수정하거나 저장소로 복사하지 않습니다.

화면은 KRDS(대한민국 정부 디자인시스템) 기준을 따릅니다. 앱에 포함한 Pretendard GOV 서체(SIL OFL 1.1, `src/video_agent/ui/assets/fonts`)로 본문 16px을 쓰고, 입력칸과 주 버튼은 40px입니다. `보기` 메뉴(`⌘+`, `⌘-`, `⌘0`)로 75~150% 범위에서 전체 UI를 확대·축소합니다. `파일` 메뉴에는 새 사건(`⌘N`), 사건 불러오기, 사건 저장(`⌘S`), 영상 추가(`⌘O`), 결과 요약이 있습니다. 머리글 오른쪽에 열린 사건과 저장 상태를, 아래 상태줄 왼쪽에 파일을 다시 연결해야 하는 영상 수를 표시합니다. 오른쪽 분석 패널은 `① 사건 등록`, `② 영상 분석`, `③ 결과 검토` 3단계 화면으로 나뉘며, 위쪽 단계 표시줄이나 아래쪽 이전·다음 버튼으로 이동합니다. 각 단계는 내용이 길면 세로 스크롤합니다. ② 단계는 `분석 설정` 카드 안에 `찾을 대상`·`확인 범위`·`계획 확인` 세 칸이 있고, 아래 고정 줄에는 `분석 계획 만들기` → `승인하고 실행` 중 지금 할 버튼 하나만 보입니다(외부 API는 `분석 계획 승인` → `외부 전송 승인` → `분석 실행`). 분석이 후보 없이 끝났고 영상 일부만 분석했다면 ③ 단계에서 영상 전체로 범위를 넓히는 제안을 보여 주며, 이때도 계획을 다시 만들고 승인해야 실행됩니다.

한 사건에 CCTV 영상을 여러 개 등록할 수 있습니다. ① 단계의 `CCTV 영상` 카드에서 영상을 추가·선택하고, 표의 각 행 끝 단추로 파일 다시 연결, 목록에서 빼기를 합니다(카메라 시각 오차는 묻지 않습니다)(카메라 위치는 묻지 않으며 이전에 저장한 값은 유지합니다). 영상이 2개 이상이면 ③ 단계 위의 카메라 탭으로 카메라별 결과를 보고, `전체 후보`로 모든 카메라의 후보를 한 번에 볼 수 있습니다. 결과 요약은 결과가 있는 카메라가 2대 이상이면 사건 전체 기준으로 열립니다. 각 시각은 해당 영상의 시작 기준이며, 카메라 사이의 시간 순서는 비교하지 않습니다.

## 분석 모드

### 시연용(샘플)

모델이나 프레임 해석 없이 승인 범위의 길이 비율로 후보를 만듭니다. 화면에 `시연용 결과 (실제 AI 분석 아님)`을 표시합니다. 내보낸 결과 요약에는 아직 `샘플 결과(실제 AI 분석 아님)`로 적힙니다.

### 로컬 VLM

현재 개발 PC에서는 Ollama 0.40.2와 `qwen3-vl:4b-instruct`, `qwen3-vl:8b-instruct`로 실제 이미지·영상 프레임 요청을 검증했습니다. 4B는 기본 개발 모델이고, 8B는 더 느리고 자원을 더 사용하는 명시적 비교 선택입니다. 앱은 Ollama `/api/show`가 `vision` capability를 반환한 모델만 목록에 올립니다. 화면에는 모델 이름 대신 크기 순으로 `빠른 분석`·`정확한 분석`(세 개 이상이면 `보통 분석`)으로 표시하고, 모델 이름은 마우스를 올렸을 때만 보입니다. `:cloud` 모델은 외부 서버에서 실행되므로 목록에서 빼고 로컬 분석으로 실행하지 않습니다. 로컬 endpoint는 loopback 주소만 허용하며 실패해도 외부 API나 샘플 결과로 전환하지 않습니다.

긴 영상은 먼저 `움직임 후보 찾기`를 실행할 수 있습니다. 이 단계는 최대 600개의 원본 PTS 기반 저해상도 표본을 비교하는 로컬 FFmpeg 전처리이며 행동 판정이나 AI 결과가 아닙니다. 일반 목적에서는 변화 점수가 큰 6초 구간을 최대 5개 보여 줍니다. 후보는 번호·구간·최대 변화·변화 크기(`큼`/`보통`/`작음`, 이번 탐색 안의 상대 비교) 열로 보여 줍니다. 체크박스로 최대 3개를 고르면 `선택 n/3`으로 표시하고, `분석 계획 만들기`를 누를 때 체크한 구간을 계획에 씁니다(별도 적용 단계 없음). 계획에는 등록된 모든 구간을 번호로 표시합니다. 일반 후보 하나를 선택하면 변화 정점 주변 12장, 두세 개를 선택하면 각 정점 주변 4장씩 총 8장 또는 12장을 사용합니다. 만든 뒤 체크를 바꾸면 계획과 승인이 무효가 되며, 새 계획을 다시 승인하기 전에는 VLM을 호출하지 않습니다. 입력 구간이 3개여도 최종 결과는 0개·1개·여러 개일 수 있고 인접 중복 결과는 정책에 따라 합쳐질 수 있습니다.

목적에 `두리번`, `주변을 살피`, `고개·머리·얼굴 방향 변화`, `반복` 같은 시간 변화 표현이 있으면 탐색 방식이 달라집니다. FFmpeg가 만든 160px 회색조 표본을 작은 타일로 나누어 일부 영역의 변화가 전체 화면 평균에 묻히지 않게 하고, 한 번의 매우 큰 변화보다 10초 동안 분산된 변화를 우선하는 `반복·미세 변화` 프로필을 사용합니다. 선택 구간을 적용하면 변화 정점에 12장을 몰지 않고 구간 전체에 시간순으로 분산합니다. 계획에는 `temporal_sequence`와 “의도·심리가 아닌 머리·얼굴·몸통 방향을 비교”하는 관찰 기준이 표시됩니다. 이 전처리도 사람이나 행동을 인식하지 않으며 점수는 확률이 아닙니다.

`temporal_sequence` 실행에서는 보통 시간순 원본 프레임을 최대 4개씩 최대 2×2 비교 보드로 묶어 로컬 VLM에 전달합니다. 모델이 받는 보드는 한 장이지만 결과와 저장 계약에는 원본 frame ID·decoded PTS 4개를 그대로 유지합니다. 단, 목적에 손가락·버튼·초인종·누르기·접촉처럼 작은 접촉 대상이 포함되면 최대 1920px 원본을 추출하고, 각 원본 시각마다 위쪽 전체 화면 보기와 아래쪽 중앙 60% 확대 보기를 1280×1080 한 장에 구성합니다. 중앙 밖 대상을 놓칠 수 있으므로 전체 보기와 함께 확인하며, 계획 화면에 이 변환을 표시합니다.

제공된 유모차 영상에서 새 전처리만 실행한 개발 확인 결과, 상위 후보에 63~73초, 78.5~88.5초, 88.5~98.5초가 포함됐습니다. 앞 두 구간은 사용자가 알려 준 63~91초의 주변을 살피는 구간과 겹치지만, 알려진 단일 영상에 대한 로컬 픽셀 변화 확인이며 VLM 탐지 성공이나 정확도 검증이 아닙니다.

새 개발 환경에는 다음처럼 런타임과 비사고형 VLM을 명시적으로 설치합니다. 모델은 약 3.3GB이며 저장소가 자동 다운로드하지 않습니다.

```bash
brew install ollama
brew services start ollama
ollama pull qwen3-vl:4b-instruct
PYTHONPATH=src ./.venv/bin/python -m video_agent
```

더 강한 로컬 비교가 필요할 때만 약 6.2GB의 `qwen3-vl:8b-instruct`를 별도로 설치하고 UI 모델 필드 또는 환경 변수로 명시합니다. 저장소는 모델을 자동 다운로드하지 않습니다.

```bash
ollama pull qwen3-vl:8b-instruct
VIDEO_AGENT_LOCAL_MODEL=qwen3-vl:8b-instruct \
  PYTHONPATH=src ./.venv/bin/python -m video_agent
```

설치 모델이 여러 개이면 현재 검증된 비사고형 동작을 위해 이름에 `instruct`가 포함된 확인 모델을 우선합니다. 다른 모델을 의도적으로 선택하려면 `VIDEO_AGENT_LOCAL_MODEL`로 고정할 수 있습니다. 수동 capability override는 해당 환경 변수의 모델과 함께 설정해야 합니다.

Ollama native `/api/chat` 형식은 이미지 입력을 base64 `images`로 보내고 JSON schema 응답을 요청합니다. 현재 로컬 계획은 16K context, 최대 출력 800 token, 응답당 최대 5개 후보, 원본 JPEG 12개를 시간순 4개씩 최대 3회로 제한합니다. 일반 시간 변화 전략은 각 묶음을 960×540 이하 비교 보드 한 장으로 합치고, 작은 접촉 정밀 목적은 시각별 전체 화면+중앙 확대 이미지 한 장을 유지합니다. 세 요청은 각각 300초를 받지 않고 프레임 추출부터 결과 검증까지 하나의 300초 예산을 공유합니다. 응답이 최종 `content` 없이 `thinking`만 포함하면 정상 결과나 후보 없음으로 처리하지 않고 명시적 모델 오류로 표시합니다.

제공된 영상 전체를 라벨 없이 움직임 탐색했을 때 최상위 제안은 92~98초였습니다. 이 제안을 선택한 0.5초 간격 12프레임 실제 분석은 45.173초에 완료되어 발과 유모차의 접촉 및 차는 것으로 보이는 후보 4개를 반환했습니다. 이는 사용자가 이미 시각을 알려 준 단일 개발 영상의 연결 검증이며, 블라인드 정확도 평가나 학대·범죄 판단이 아닙니다.

### 외부 API VLM

앱에서 `외부 API VLM — 별도 전송 승인`을 선택하면 OpenAI API 키 입력칸이 나타납니다. 키는 암호형으로 표시되고 현재 앱 프로세스의 메모리에서만 HTTP 인증 헤더에 사용되며, 설정·결과·로그에는 저장하지 않습니다. 영상 입력을 지원하는 OpenAI 모델 ID를 직접 입력합니다. 별도 확인란은 없고, 계획에 적힌 전송 사진 수·시각을 보고 `외부 전송 승인`을 누르는 것이 이 AI에 사진을 보낸다는 확인을 겸합니다(승인 전에는 실행하지 않음). 모델 ID는 계정에서 실제 사용할 수 있는 이미지 입력 지원 모델인지 OpenAI 모델 문서에서 확인해야 합니다.

기본 공급자와 endpoint는 `openai`, `https://api.openai.com/v1/chat/completions`입니다. 화면 대신 `OPENAI_API_KEY` 환경 변수로 키를 전달할 수도 있습니다. `.env.example`은 변수 이름과 공개 설정만 제공하며 실제 비밀값을 포함하지 않고, 앱은 `.env`를 자동으로 읽지 않습니다.

```bash
export VIDEO_AGENT_EXTERNAL_PROVIDER='openai'
export VIDEO_AGENT_EXTERNAL_ENDPOINT='https://api.openai.com/v1/chat/completions'
export VIDEO_AGENT_EXTERNAL_PROTOCOL='openai_chat_completions'
export VIDEO_AGENT_EXTERNAL_MODEL='vision-model-id'
export VIDEO_AGENT_EXTERNAL_MODEL_SUPPORTS_VISION=true
export OPENAI_API_KEY='실제 값은 셸/비밀 저장소에서만 설정'
PYTHONPATH=src ./.venv/bin/python -m video_agent
```

계획 화면은 공급자, 목적지 origin, 목적 텍스트, JPEG 프레임 수와 원본 시각을 보여 줍니다. 분석 계획 승인 후에도 외부 전송을 별도로 승인해야 실행됩니다. 원본 영상 전체, PDF, 라벨 JSON은 전송 계획에 포함하지 않습니다.

공식 OpenAI 문서는 API 키를 코드나 공개 저장소에 넣지 말고 환경 변수 또는 비밀 관리 수단으로 제공하도록 권고합니다. 모델별 이미지 입력은 [Images and vision](https://developers.openai.com/api/docs/guides/images-vision), 키 관리는 [Production best practices](https://developers.openai.com/api/docs/guides/production-best-practices)를 기준으로 확인합니다. 현재 구현은 실제 OpenAI 과금 호출을 수행하지 않고 가짜 응답으로 인증 헤더·이미지 요청 구성·키 미저장을 검증했습니다. 실제 호출은 사용자가 키·모델·전송 프레임 범위를 확인한 뒤 별도로 검증해야 합니다.

## 시간과 결과 정책

- 계약 시간은 원본 시작 기준 초(`float`), Qt UI 경계만 밀리초(`int`)입니다.
- 가변 프레임률 여부를 FPS 값 하나로 확정하지 않으며 프레임 번호/FPS로 시각을 만들지 않습니다.
- 추출 결과는 요청 시각과 FFmpeg가 디코딩한 원본 PTS를 함께 기록합니다.
- 모델 구간이 승인 범위를 벗어나거나 `end <= start`이면 결과를 거부합니다. 승인 범위 안의 확인용 재생 범위만 근거 프레임을 포함하지 않는 경우에는 근거 앞뒤 1초 범위로 대체하고 그 사실을 불확실성에 기록합니다.
- 모델 실패를 샘플 결과로 대체하지 않습니다.
- `completed` 빈 결과, `partial`, `failed`, `canceled`를 서로 다르게 표시합니다.
- 후보의 시작·종료는 행동 경계가 아니라 사람이 확인할 재생 범위이며, 실제 관찰 프레임 원본 시각을 별도로 표시합니다.
- 후보를 클릭하면 저장된 확인용 범위와 관찰 시각은 바꾸지 않고, 맥락 확인을 위해 확인용 범위 시작의 최대 1초 전으로 이동합니다. 영상은 근거 범위를 지나 계속 재생되므로 짧은 후보의 직전·직후 동작을 원본에서 확인할 수 있습니다.
- `evidence`는 화면에서 보이는 자세·신체 부위·물체·변화를 설명해야 합니다. 프레임 ID만 반환한 항목은 정상 후보로 받지 않습니다.
- 여러 배치가 정규화된 관찰 요약이 같고, 재생 범위가 겹치며, 근거 시각이 1초 이내로 이어지는 후보를 반환한 경우에만 하나의 확인 항목으로 묶습니다. 원래 근거 시각과 묶음 사실은 보존합니다.
- 실제 결과의 `model_execution`에는 원본 입력 프레임 수와 실제 공급자 이미지 수·크기·표현 방식, `prompt_version`, 각 완료 배치의 후보 수가 기록됩니다. 이는 모델 정확도 점수가 아니라 실행 재현성과 빈 결과 진단 정보입니다.
- '오래 머무름'처럼 지속 시간이 핵심인 목적에 초·분 기준이 없으면 Agent가 먼저 질문합니다. 모델이 지속성을 단정하려면 서로 다른 관찰 시각 2개 이상과 승인된 시간 기준을 충족해야 합니다. 결과는 첫·마지막 표본 시각, 표본 간 경과 시간, 중간 연속성 미확인을 따로 표시합니다.
- 반복·두리번거림·방향 변화를 단정하는 모델 결과는 서로 다른 관찰 시각 2개 이상을 근거로 제시해야 합니다. UI는 관찰 시각 수와 표본 간격을 보여 주며 중간 동작과 실제 반복 횟수는 원본에서 확인하도록 표시합니다.
- 진행률을 모르는 메타데이터/추출/모델 호출은 불확정 상태로 표시합니다.
- 검토 기록은 사람의 판단입니다. 모델 결과(`AnalysisJob`)를 바꾸지 않고 분석기에 보내지 않으며, 후보는 `job_id`와 후보 번호로 연결합니다.
- 범위 재생 버튼은 선택 범위를 원본 길이 안으로 맞추고, 범위 끝에서 재생을 멈춥니다.
- 결과 요약은 저장된 결과와 검토 기록을 규칙에 따라 정리하며 AI를 호출하지 않습니다. 사전 정보를 영상에서 확인한 사실처럼 쓰지 않고, 범죄 성립이나 의도를 판단하는 문구를 만들지 않습니다.

## 사용자 데이터

기본 위치:

```text
~/Library/Application Support/VideoAnalysisAgent/settings.json
~/Library/Application Support/VideoAnalysisAgent/cases/*.json
~/Library/Application Support/VideoAnalysisAgent/results/*.json
~/Library/Application Support/VideoAnalysisAgent/reviews/<job-id>.json
~/Library/Caches/VideoAnalysisAgent/<job-id>/
```

`reviews/`에는 결과별 검토 기록(판단·메모·태그·북마크·완료 시각·확인 시간)을 저장합니다. 결과 요약 HTML은 사용자가 고른 위치에만 저장하며, 요약 창에서 고친 문구는 앱에 저장하지 않습니다.

설정에는 API 키 값이 아니라 환경 변수 이름만 저장합니다. 결과에는 원본 파일 경로 대신 영상 ID, 분석 목적·범위, 요청/디코딩 시각, 모델·context·출력 한도·입력 해상도, 실행 시간과 결과 출처를 저장합니다. 캐시는 앱 marker가 있는 작업 폴더만 정리합니다. 테스트에서는 `VIDEO_AGENT_DATA_DIR`, `VIDEO_AGENT_CACHE_DIR`로 격리할 수 있습니다.

## 테스트

```bash
QT_QPA_PLATFORM=offscreen PYTHONPATH=src \
  ./.venv/bin/python -m unittest discover -s tests -v
```

테스트는 순수 계약, Agent 상태, 가짜 공급자, 저장소, 오프스크린 UI와 짧은 합성 H.264 영상의 FFprobe/FFmpeg 처리를 포함합니다. 이는 실제 CCTV 정확도나 실제 VLM 추론 검증이 아닙니다.

## 개발용 `.app`

```bash
./.venv/bin/python -m pip install -r requirements-dev.txt
./scripts/build_macos_app.sh
open dist/VideoAnalysisAgent.app
```

결과는 `dist/VideoAnalysisAgent.app`입니다. 모델 가중치, 영상, 키와 Homebrew FFmpeg는 번들에 포함하지 않습니다. 현재 빌드는 arm64이며 PyInstaller의 ad-hoc 서명만 있습니다. 개발자 인증서 서명·공증·배포 호환성은 미검증입니다.

`.app`을 실행하는 Mac에도 FFmpeg/ffprobe와 Ollama가 별도로 설치되어 실행 중이어야 하며, 사용할 VLM도 Ollama 사용자 저장소에 있어야 합니다.
